# Кнопка «Инструкция» в админке — PDF с инструкцией и историей изменений

Дата: 2026-09-28
Статус: утверждён

## 1. Задача

Заказчики (эксперт и продюсеры), получившие доступ к админке (роль `admin`), должны иметь под рукой
актуальную инструкцию по пользованию и понимать, что изменилось в боте с прошлого раза. Заменяет ранее
запланированный отдельный «документ по пользованию» ссылкой (см. §5 спеки
`2026-09-27-client-admin-access-design.md`) — вместо ссылки на внешний живой документ инструкция теперь
доставляется файлом прямо в боте, и её обновление — обязанность разработчика (агента) при каждом
функциональном изменении бота, а не разовая задача.

## 2. Решения (утверждено с заказчиком в диалоге)

| Вопрос | Решение |
|---|---|
| Кому видна кнопка | Владельцу и заказчику с ролью `admin` — на главном экране админки, 5-м пунктом (после ⚙️ Настройки) |
| Формат | PDF, отправляется документом в чат по нажатию кнопки |
| Где хранится файл | Внутри `bot/` (`bot/assets/client-guide.pdf`), не в `docs/` — Dockerfile копирует в образ только `COPY bot ./bot`, файл вне `bot/` на сервер не попадёт |
| Как поддерживается | Markdown-исходник в `docs/client-guide/client-guide.md` (для чтения/правки), PDF генерируется из него и коммитится вместе с кодом при каждом изменении |
| Версионирование | Дата обновления в шапке документа («Обновлено: ДД.ММ.ГГГГ») — без отдельного счётчика версий |
| Содержание | Шапка с датой; коротко что делает бот; как пользоваться админ-панелью по разделам (Воронка/Рассылки/Статистика/Настройки); история изменений по датам. Без раздела о том, что доступно роли `admin`, а что только владельцу — заказчику нужна инструкция по пользованию, не разбор прав доступа |

## 3. Реализация (по образцу уже существующего `a:stat:file`)

В `bot/handlers/admin/stats.py` уже есть ровно такой же паттерн — кнопка «Скачать таблицу»
(`a:stat:file`) отдаёт `.xlsx` с диска через `FSInputFile` + `call.message.answer_document(...)`.
Новая кнопка — то же самое, но со статичным файлом вместо генерируемого на лету.

- Создать: `docs/client-guide/client-guide.md` — источник текста (markdown), не участвует в рантайме.
- Создать: `bot/assets/client-guide.pdf` — сгенерированный файл, именно его бот отправляет.
- Модифицировать: `bot/handlers/admin/__init__.py`:
  - добавить пункт `[("📖 Инструкция", "a:guide")]` пятым в `MENU`;
  - добавить `GUIDE_PDF_PATH = Path(__file__).resolve().parents[2] / "assets" / "client-guide.pdf"`
    (от `bot/handlers/admin/__init__.py` наверх до `bot/`, как `SCHEMA_PATH` в `bot/db.py`);
  - добавить `@router.callback_query(F.data == "a:guide")` — этот роутер уже целиком под `AdminFilter`
    (строка 15), значит и владелец, и роль `admin` его видят автоматически, роль `stats` — нет
    (отдельного `require_owner` не нужно, кнопка не владельческая).

## 4. Логика

- Обработчик: если файла нет на диске — не падает, а `call.answer("Файл инструкции не найден, сообщите
  разработчику", show_alert=True)` (тот же принцип, что и остальные операции с файлами в проекте —
  не молчать при ошибке).
- Если файл есть — `await call.message.answer_document(FSInputFile(GUIDE_PDF_PATH, filename=
  "Инструкция.pdf"))`, `await call.answer()`.

## 5. Процесс поддержания в актуальном состоянии

При каждом функциональном изменении бота (часть обычного рабочего процесса, не отдельная задача):
1. Правится `docs/client-guide/client-guide.md` — новая строка в истории изменений и, если поменялся
   пользовательский сценарий в разделах Воронка/Рассылки/Статистика/Настройки, правка раздела.
2. PDF перегенерируется из markdown.
3. Оба файла коммитятся вместе с кодом изменения.

## 6. Тестирование

- Нажатие `a:guide` владельцем отправляет документ (`"SendDocument" in session.names()`), по образцу
  `test_stats_file_button_sends_document`.
- Нажатие `a:guide` заказчиком с ролью `admin` — тоже отправляет документ.
- Роль `stats` не проходит `AdminFilter` вообще (уже покрыто существующими тестами `/admin` для роли
  `stats` — отдельного теста на `a:guide` для неё не требуется, это регрессия уровня роутера, а не
  этой кнопки).
- Отсутствующий файл (подменить `GUIDE_PDF_PATH` на несуществующий путь) — алерт, не падение,
  `"SendDocument" not in session.names()`.

## 7. Вне охвата

- Локализация / несколько языков инструкции — не запрашивалось.
- Автогенерация changelog из git-истории коммитов — changelog в PDF пишется вручную (агентом) как
  человеко-читаемый список для заказчика, не техническая история коммитов.
- Отдельная кнопка «Инструкция» для обычных подписчиков воронки — не нужна, инструкция только для
  заказчиков в админке.
