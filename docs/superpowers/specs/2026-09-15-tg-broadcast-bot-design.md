# Телеграм-бот: рассылки + воронка с проверкой подписки и прогревом

Дата: 2026-09-15
Статус: утверждён

## 1. Задача

Бот для холодного трафика, который:
- на `/start` отдаёт кружок-приветствие и меню с проверкой подписки на канал;
- после подтверждения подписки выдаёт материал;
- дальше в течение заданного времени шлёт цепочку прогревающих сообщений;
- позволяет владельцу в любой момент делать массовые рассылки (фото, видео, кружочки, файлы) по базе.

Весь контент владелец загружает сам, прямо в бота. В коде не зашито ни одного текста воронки, ни одного файла.

## 2. Решения (утверждено с заказчиком)

| Вопрос | Решение |
|---|---|
| Хостинг | Ubuntu-сервер, Docker + docker-compose |
| Архитектура | aiogram 3 + SQLite, один процесс, встроенный планировщик |
| Настройка прогрева | в админке бота, без редеплоя |
| Выдача материала | файлы/видео в чат + invite-ссылка в закрытый канал + текст со ссылкой (комбинируется) |
| Проверка подписки | только на шагах с флагом «требует подписку» (доступы, закрытые материалы, инсайты) |
| Тест → прод | один бот, канал переключается в админке |

## 3. Стек

- Python 3.11 (в Docker), aiogram 3.x, aiosqlite
- SQLite в режиме WAL, файл в volume `./data`
- Планировщик — asyncio-задача внутри процесса, тик раз в 60 секунд
- Никаких Redis/Postgres/Celery: одна воронка, десятки тысяч пользователей — SQLite держит с запасом

## 4. Данные

### users
`tg_id` (PK), `username`, `first_name`, `started_at`, `source` (payload из deep-link `?start=ig_reels`), `status` (active / blocked / stopped), `is_subscribed` (кэш), `sub_checked_at`, `material_sent_at`.

### media
`id`, `slug` (уникальный, человекочитаемый), `kind` (photo / video / video_note / document / audio / voice / animation / sticker), `file_id`, `file_unique_id`, `caption`, `created_at`.
Загрузка: админ отправляет боту файл → бот сохраняет `file_id` и просит имя.
**Важно:** `file_id` привязан к конкретному боту. При смене токена медиатеку надо перезаливать.

### funnel_steps
`id`, `position`, `delay_seconds` (от момента входа в воронку), `requires_subscription` (0/1), `text`, `media_id` (nullable), `buttons_json` (список `{text, url}`), `enabled`.

### user_steps — очередь отправок
`id`, `user_id`, `step_id`, `due_at`, `status` (pending / sent / skipped / held / failed), `attempts`, `last_error`, `sent_at`.
Уникальный индекс `(user_id, step_id)` — защита от дублей при рестарте.

### broadcasts / broadcast_targets
`broadcasts`: `id`, `created_at`, `created_by`, `segment`, `payload_json` (список сообщений), `scheduled_at`, `status` (draft / queued / running / done / cancelled), `stats_json`.
`broadcast_targets`: `broadcast_id`, `user_id`, `status` (pending / sent / blocked / failed), `error`. Прогресс переживает рестарт контейнера.

### settings
key-value: `channel_id`, `channel_url`, `private_channel_id`, `welcome_note_media_id`, `menu_text`, `not_subscribed_text`, `material_*`, `reminder_text`.

## 5. Сценарий пользователя

1. `/start` (возможно с payload) → пользователь создаётся или обновляется, источник запоминается.
2. Бот шлёт кружок (`video_note` из настроек), если он задан.
3. Меню: текст + инлайн-кнопки **[Подписаться]** (url канала) и **[Я подписан]** (callback `check_sub`).
4. По `check_sub` — `getChatMember`. Валидные статусы: `member`, `administrator`, `creator`, а также `restricted` с `is_member=true`. Не подписан → всплывашка «Подписки не видно», меню остаётся.
5. Подписан → выдача материала: последовательность сообщений (медиа из медиатеки + тексты + кнопки). Если задан закрытый канал — генерируется персональная invite-ссылка (`createChatInviteLink`, `member_limit=1`).
6. Ставим в очередь все включённые шаги воронки: `due_at = now + delay_seconds`.
7. `/reset` — очистить своё прохождение и пройти заново (для теста).

## 6. Прогрев

Тик раз в минуту: выбираются `user_steps` со `status='pending' AND due_at <= now`, партиями.

- Шаг с `requires_subscription=1`: перед отправкой проверяется подписка. Нет подписки → уходит напоминание с кнопками, шаг переносится на `+6 ч`, `attempts += 1`. После 3 попыток — `skipped`. Остальные шаги цепочки при этом идут своим чередом.
- Шаг без флага уходит всем активным.
- `403 Forbidden` (заблокировал бота) → `users.status = blocked`, все его pending-шаги → `skipped`.
- `429` → ждём `retry_after`, повторяем.
- Прочие ошибки → `attempts += 1`, перенос на +30 мин, после 3 попыток `failed` + запись в лог.

## 7. Админка (`/admin`, доступ по `ADMIN_IDS`)

- **📤 Рассылка** — админ шлёт боту одно или несколько сообщений любого типа, бот собирает их в черновик → предпросмотр → «тест себе» / «отправить» / «запланировать». Сегменты: все, подписанные, не подписанные, дошедшие до материала, по источнику. Отчёт: доставлено / заблокировали / ошибки.
- **🎬 Медиатека** — загрузить, список, просмотр, удалить.
- **🔥 Прогрев** — список шагов, добавить (задержка → контент → нужна ли подписка → кнопки), изменить порядок и задержки, включить/выключить, удалить, «прогнать на себе» (все задержки по 10 секунд), экспорт/импорт воронки в JSON.
- **⚙️ Настройки** — кружок приветствия, тексты, публичный канал, закрытый канал. При смене канала бот проверяет, что он там админ, и только тогда сохраняет.
- **📊 Статистика** — всего / активных / заблокировали / подписаны / дошли до материала, разбивка по источникам, выгрузка пользователей в CSV.

## 8. Отправка и надёжность

Единая обёртка `safe_send`:
- глобальный лимитер ~20 сообщений/сек (потолок Telegram — 30);
- `TelegramRetryAfter` → sleep + повтор;
- `TelegramForbiddenError` → пометить пользователя `blocked`;
- `TelegramBadRequest` → лог + `failed`.

Рассылка копирует исходные сообщения через `copy_message` — форматирование, медиа и подписи сохраняются один в один, без перезаливки файлов.

SQLite: `journal_mode=WAL`, `busy_timeout=5000`. Ежедневный бэкап БД в `data/backups/` (14 копий).

## 9. Тесты

pytest на логику, которая ломается тихо:
- выборка готовых к отправке шагов (границы времени, статусы);
- поведение при отписке: перенос, счётчик попыток, skip после лимита;
- обработка 403/429 в `safe_send`;
- rate-limiter выдерживает заданную скорость;
- постановка воронки в очередь без дублей при повторном `/start`.

Админка проверяется по ручному чек-листу в README.

## 10. Деплой

`Dockerfile` (python:3.11-slim), `docker-compose.yml` с volume `./data:/app/data`, `.env` из `.env.example`.
Порядок: создать бота у @BotFather → добавить бота админом в канал → заполнить `.env` → `docker compose up -d` → `/admin` в боте → залить кружок и материалы → настроить шаги прогрева.

## 11. Вне рамок (YAGNI)

Веб-интерфейс, оплаты, несколько воронок одновременно, A/B-тесты, мультиязычность, Postgres. Структура позволяет добавить позже, но сейчас не делаем.
