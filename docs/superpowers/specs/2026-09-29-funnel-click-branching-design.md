# Воронка с ветвлением по клику и автовыдачей урока

Дата: 2026-09-29
Статус: дизайн утверждён в диалоге, ждёт ревью спеки

## 1. Задача

Заказчик описал воронку из 12 этапов. Тексты, кнопки и тайминги вносятся инструкцией через админку,
но три требования текущий бот выполнить не может:

1. **Автовыдача урока.** Кто нажал /start, но не подписался (или не нажал «Проверить подписку»), должен
   получить урок сам через 1 час. Сейчас `deliver_material` вызывается только из
   `check_subscription_flow` после успешной проверки подписки — без нажатия человек урока не получит никогда.
2. **Знать, что человек перешёл на урок.** Кнопки — только URL (`ContentBlock.keyboard()`), Telegram не
   сообщает боту о нажатии URL-кнопки, клики нигде не учитываются.
3. **Ветвление по клику.** Пуши №1–5 («Смотреть урок») идут, только пока клика нет. После клика они
   отменяются, а «первый прямой призыв на разбор» приходит через 1 час после клика; всё дальнейшее едет за ним.
   Если клика так и не было — воронка продолжается по таймеру через 12 ч после пуша №5.

Вне рамок: тексты постов, медиа и кружок, отслеживаемые ссылки через свой домен (см. §3.2 — оставлена
точка расширения).

## 2. Как это работает сейчас

- `funnel_steps.delay_seconds` — **абсолютный** сдвиг от момента выдачи урока. `FunnelRepo.enqueue` ставит
  каждому включённому шагу `due_at = now + delay_seconds` сразу для всех шагов; `backfill_step` считает
  от `users.material_sent_at`. Условий и ветвления нет, кроме подписки (`requires_subscription`, `on_unsub`).
- `deliver_material` отмечает `material_sent_at` только в конце (`mark_material_sent`, COALESCE).
- Кнопки: `buttons_json = [{"text","url"}]`, админ вводит «Текст | ссылка» построчно (`parse_buttons`).

**Решение по моделям задержек:** абсолютную модель сохраняем, накопленные сдвиги считаем сами (см. §7).
Переход на «от предыдущего поста» — лишний рефакторинг `enqueue`/`backfill_step` и риск для боевых воронок.

## 3. Дизайн

### 3.1 Автовыдача урока

- Настройка `auto_deliver_minutes` (по умолчанию `60`, `0` — выключено), правится в админке в разделе
  настроек рядом с `gate_retry_hours`.
- Каждый тик планировщик (`Scheduler.tick`, до обработки шагов) берёт пользователей:
  `status='active' AND material_sent_at IS NULL AND started_at + minutes*60 <= now` (не больше `BATCH`) и
  выдаёт им урок, **не проверяя подписку**.
- **Защита от двойной выдачи.** Новая колонка `users.deliver_claim_at`. Единый вход
  `deliver_material_once(bot, deps, chat_id, *, auto=False) -> bool` сначала атомарно занимает пользователя:

  ```sql
  UPDATE users SET deliver_claim_at = :now
  WHERE tg_id = :id AND material_sent_at IS NULL
    AND (deliver_claim_at IS NULL OR deliver_claim_at < :now - 600)
  ```

  `rowcount == 0` → уже выдаётся/выдан, ничего не шлём. Оба пути (успешная проверка подписки и планировщик)
  идут через эту функцию. Занятая, но не завершённая выдача (падение процесса) снова доступна через 10 минут.
  При исключении внутри выдачи claim снимается.
- При автовыдаче неподписчику **не отправляется персональная ссылка в закрытый канал** (это награда за
  подписку); текст материала и медиа уходят как обычно. Если закрытый канал не настроен — разницы нет.
- После выдачи воронка ставится в очередь как обычно (`enqueue`); шаги с `requires_subscription` по-прежнему
  проверяются шлюзом при отправке.

### 3.2 Кнопка-прокладка «считать клик»

- Синтаксис в редакторе кнопок: `Смотреть урок | https://tkpdt.ru/lendingi150 | клик` — третье поле
  (регистр не важен) включает отслеживание. В JSON: `{"text","url","track":true}`. Без третьего поля кнопка —
  обычная ссылка (обратная совместимость).
- `ContentBlock.keyboard()` для кнопки с `track` строит **callback-кнопку** `lc:<h>`, где
  `h = sha1(url)[:16]` (лимит callback_data — 64 байта, сам URL не влезет). Действует в шагах прогрева и в
  блоках материала; в рассылках и «повторном /start» флаг игнорируется (кнопка остаётся ссылкой).
- Хендлер `lc:<h>`: находит URL, перебирая `track`-кнопки шагов и блоков материала (их единицы; таблицы
  не нужно), вызывает `record_click(user_id)`, отвечает `callback.answer()` и присылает короткое сообщение
  «Вот урок 👇» с обычной URL-кнопкой на этот адрес. Если хеш не найден (админ сменил ссылку) — alert
  «Ссылка устарела, напишите /start».
- `record_click` — отдельная функция сервиса: единая точка, на которую позже можно повесить отслеживаемую
  ссылку через свой домен, не меняя ветвление.
- Текст ответа и подпись кнопки — настройки `lesson_link_text` («Вот урок 👇») и `lesson_link_btn`
  («Открыть урок»).

### 3.3 Ветвление после клика

Новые поля:

| Таблица | Поле | Смысл |
|---|---|---|
| `users` | `lesson_clicked_at INTEGER` | время **первого** клика (NULL — не было) |
| `users` | `deliver_claim_at INTEGER` | защита автовыдачи (§3.1) |
| `users` | `funnel_fast INTEGER NOT NULL DEFAULT 0` | воронка поставлена в быстром тестовом режиме |
| `funnel_steps` | `stop_on_click INTEGER NOT NULL DEFAULT 0` | пуш отменяется после клика |
| `funnel_steps` | `after_click_seconds INTEGER` | у «первого призыва»: через сколько после клика слать |

`FunnelRepo.apply_click(user_id, click_at) -> None`, вызывается из `record_click`, только если
`lesson_clicked_at IS NULL` (проверка и запись — один `UPDATE ... WHERE lesson_clicked_at IS NULL`,
`rowcount == 1` → продолжаем; повторный клик — no-op):

1. Все `pending` шаги пользователя с `stop_on_click=1` → `status='skipped'`, `last_error='клик по уроку'`.
2. Якорь A — первый по `position` шаг пользователя в статусе `pending` с `after_click_seconds IS NOT NULL`.
   Якоря нет (уже отправлен/пропущен/не задан) → сдвигов нет.
3. `new_due = click_at + A.after_click_seconds`, `delta = new_due - A.due_at`. Всем `pending` шагам
   пользователя с `position >= A.position` делаем `due_at += delta` (delta может быть отрицательной —
   «подтянуть вперёд»; интервалы между постами сохраняются).
4. Всё в одной транзакции.

Сценарии: клик до первого пуша — все 5 пушей отменены, призыв в клик+1ч; клик между пушами — оставшиеся
отменены; клик после пуша №5, до призыва — призыв в клик+1ч (может сдвинуть и вперёд, и назад);
клик после призыва — сдвигов нет; клика нет — цепочка идёт по накопленным сдвигам.

Быстрый тестовый режим: `enqueue(fast=True)` (10 с × номер шага) ставит `users.funnel_fast=1`; «после клика» в этом режиме —
`FAST_STEP_SECONDS` (10 с). `users.reset()` обнуляет `lesson_clicked_at`, `deliver_claim_at`, `funnel_fast`.
Не подписанный пользователь: клик доступен только тем, кто получил урок, ветвление на него распространяется так же.

### 3.4 Админка

- Карточка шага показывает «🛑 Отменяется после клика: да/нет» и «🎯 После клика: через 1 ч» (если задано).
- В «⋯ Ещё»: переключатель «Отменять после клика», кнопка «Задержка после клика» (ввод как у обычной
  задержки через `parse_delay`; `-` — убрать).
- `export_json` / `import_json` переносят новые поля шагов (в т.ч. `track` внутри `buttons_json`).
- `auto_deliver_minutes` — в настройках.

## 4. Обработка ошибок и граничные случаи

- Клик от пользователя, у которого нет шагов в очереди (например, воронка отключена) — записывается время,
  ветвление ничего не меняет.
- Заблокировавший бота: очередь очищается существующим `mark_blocked`; автовыдача берёт только `active`.
- Гонка «подписался ровно когда сработала автовыдача» — закрыта claim'ом (§3.1).
- Два быстрых клика подряд — второй no-op (условный UPDATE).
- Шаг, удалённый админом до клика, — просто отсутствует в очереди.
- `edit`/`move_step` уже отправленных/ожидающих шагов — как раньше (`move_step` не пересчитывает очередь).

## 5. Тесты

Функционально — всё в `tests/`, TDD:

- автовыдача: выдаёт по таймеру; не выдаёт тем, кто уже получил; не выдаёт при `0`; не выдаёт
  `blocked`; нет двойной выдачи при одновременном подтверждении подписки и тике; не шлёт приватную ссылку
  неподписчику; claim освобождается при ошибке и переживает 10 минут;
- `parse_buttons`: третье поле «клик», регистр, обратная совместимость; `keyboard()` строит callback;
  callback_data ≤ 64 байта;
- хендлер `lc:`: записывает клик, шлёт ссылку, устаревший хеш, повторный клик;
- `apply_click`: 5 сценариев из §3.3, сдвиг вперёд/назад, сохранение интервалов, идемпотентность,
  быстрый режим, `reset`;
- админка: переключатель и ввод задержки после клика; export/import.
