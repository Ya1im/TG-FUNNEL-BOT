# Кастомные эмодзи и единое сообщение «фото + подпись» — дизайн

## Проблемы
1. Кастомные эмодзи заказчика не доходят до людей.
2. Одни посты с фото уходят единым сообщением, другие — двумя (фото, затем текст).

## Причины (по коду и документации Telegram)
1. Бот читает эмодзи верно: `Message.html_text` даёт `<tg-emoji emoji-id="…">😀</tg-emoji>`, при отправке это
   уходит в HTML-режиме. Но Telegram (Bot API 9.0, 2025-04) показывает custom emoji в сообщениях бота только если у
   ВЛАДЕЛЬЦА бота есть Telegram Premium (или у бота купленные на Fragment юзернеймы). Иначе сущность молча
   игнорируется и виден обычный эмодзи. Кодом это не обойти — нужна диагностика.
2. `ContentBlock.factories` сравнивал с лимитом подписи 1024 длину HTML-строки, а не видимого текста. Каждое
   `<tg-emoji …>` (≈50 символов), `<a href>` и `<b>` раздували длину; пост с 10 эмодзи «не влезал» и резался.

## Решение
- `visible_len(html)` — длина видимого текста (без тегов, с раскрытыми сущностями). Подпись к медиа единая,
  пока видимая длина ≤ текущего лимита.
- Лимит подписи оптимистичный: 2048 (Premium-заказчик пишет подписи до 2048). Если Telegram отвечает
  «caption is too long», отправка автоматически повторяется разбитой (медиа + текст), лимит запоминается как 1024
  на время работы процесса, чтобы не делать лишних неудачных запросов.
- Кнопка остаётся одна (правило прошлой версии).
- `SendOutcome.caption_split` — пост ушёл двумя сообщениями из-за длины; `SendOutcome.custom_emoji_lost` — в тексте
  были кастомные эмодзи, а Telegram вернул сообщение без custom_emoji-сущностей.
- «👁 Показать» (шаг, сообщение шага, материал, повторный /start, рассылка) после отправки присылает админу
  пояснение, если случилось одно из двух. Общий помощник `common.send_preview`.

## Вне рамок
Кастомные эмодзи в тексте кнопок; текст без медиа длиннее 4096.
