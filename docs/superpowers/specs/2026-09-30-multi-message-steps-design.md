# Несколько сообщений в шаге прогрева — дизайн

## Цель
Админ может собрать шаг прогрева из нескольких сообщений с любыми медиа (текст, фото, видео, кружок, файл,
аудио, голосовое, гифка, стикер) — по технологии рассылки. Шаг остаётся одной «единицей» цепочки:
задержка следующего шага считается от отправки ПОСЛЕДНЕГО сообщения этого шага.

## Решения (согласовано с заказчиком)
- Кнопки-ссылки у каждого сообщения свои (можно не вешать вовсе).
- Пауза между сообщениями внутри шага — около 1 секунды (`STEP_MESSAGE_PAUSE = 1.0`).
- Хранение: сообщение №1 остаётся в прежних колонках шага (`text`, `media_id`, `buttons_json`),
  остальные — в новой колонке `funnel_steps.extra_messages_json` (список
  `{"text","media_kind","file_id","buttons","media_id"}`, формат как у рассылки). Старые шаги работают
  без изменений; миграция добавляет одну колонку.

## Данные (`bot/repo/funnel.py`)
- `step_messages(row) -> list[dict]` — все сообщения шага по порядку (первое из колонок + extras).
- `blocks_from_row(row) -> list[ContentBlock]`; `block_from_row` (первое сообщение) сохраняется.
- `FunnelRepo.set_messages(step_id, items)` — пишет items[0] в прежние колонки, остальные в extras.
  Пустой список запрещён (ValueError).
- `add_step(..., extra_messages=None)`.
- `list_steps` / `due_steps` отдают `extra_messages_json`.
- Экспорт/импорт: ключ `extra_messages` (`text`, `media_slug`, `buttons`); импорт находит медиа по slug.

## Отправка (`bot/scheduler.py`)
Шаг = последовательная отправка всех блоков с паузой `STEP_MESSAGE_PAUSE` (через `self.sleep`).
Номера всех отправленных сообщений собираются в один журнал (`kind='step'`) — отзыв удалит их все.
- Сообщение №1 не ушло — прежняя логика (blocked / повтор / failed).
- №1 ушло, а позднее сообщение не ушло из-за ошибки — шаг считается отправленным (`mark_sent`),
  чтобы человеку не пришли дубли; в лог пишется предупреждение.
- Пользователь заблокировал бота посреди шага — отправка прекращается, очередь очищена (как сейчас).

## Админка (`bot/handlers/admin/funnel.py`)
- Карточка шага: вместо «✏️ Текст/медиа» и «🔘 Кнопки» — «📨 Сообщения (N)»; «👁 Показать» шлёт весь набор.
  Старые callback `a:fun:ed:` / `a:fun:btn:` остаются рабочими (правят сообщение №1).
- Список сообщений шага `a:fun:msgs:<step>`: строки-кнопки сообщений, «➕ Добавить сообщение», «⬅️ К шагу».
- Экран сообщения `a:fun:m:<step>:<idx>`: 👁 Показать, ✏️ Текст/медиа, 🔘 Кнопки, ⬆️/⬇️, 🗑 Удалить
  (единственное сообщение удалить нельзя).
- Добавление в существующий шаг: FSM `FunnelMsgAdd.collecting` — каждое присланное сообщение сразу
  сохраняется; «✅ Готово» возвращает к списку.
- Создание шага: задержка → `FunnelAdd.collecting` (копим сообщения в FSM, счётчик правится в одном
  сообщении, как в рассылке) → «✅ Готово» → шаг создаётся, открывается список сообщений
  с подсказкой, где повесить кнопки.
- Все правки сразу пишутся в базу (черновика нет).
