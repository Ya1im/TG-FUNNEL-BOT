# Телеграм-бот: воронка с проверкой подписки + массовые рассылки

Бот берёт холодный трафик, проверяет подписку на канал, выдаёт материал и дальше сам
ведёт человека цепочкой прогрева. Плюс массовые рассылки любым типом контента
(фото, видео, кружки, файлы) по всей базе или по сегменту.

Весь контент заливается через админку прямо в боте — в коде ничего править не надо.

---

## Что умеет

**Сценарий пользователя**
1. `/start` → приходит кружок (или любое медиа, что выберешь).
2. Меню с кнопками **«Подписаться»** (ведёт в канал) и **«Я подписан»**.
3. По кнопке «Я подписан» бот спрашивает Telegram, состоит ли человек в канале.
4. Если да — выдаёт материал: файлы, видео, тексты со ссылками + персональную
   одноразовую ссылку в закрытый канал (если он настроен).
5. Дальше по расписанию идут прогревающие сообщения.

**Прогрев**
- Любое число шагов, задержка у каждого своя: `30м`, `2ч`, `3д`, `1д 4ч`.
- Флаг 🔒 на шаге — он уйдёт только подписчику. Если человек отписался, ему придёт
  напоминание, шаг подождёт 6 часов и повторится (до 3 раз), остальные шаги идут своим чередом.
- Кнопка «Прогнать на себе» — вся цепочка на тебе с задержками по 10 секунд.
- Экспорт/импорт цепочки в JSON — бэкап и перенос.

**Рассылки**
- Шлёшь боту сообщения (можно несколько подряд) → выбираешь сегмент → отправляешь
  или планируешь на время.
- Сегменты: все активные, подписанные, не подписанные, получившие материал, не получившие.
- Скорость ~20 сообщений/сек, 429 от Telegram переживает, заблокировавших помечает и
  снимает с прогрева. Прогресс сохраняется: если контейнер перезапустится, рассылка
  досылает остаток, а не начинает заново.

**Ещё**
- Статистика: кто, сколько, откуда (источники из deep-link `?start=ig_reels`), выгрузка CSV.
- Ежедневный бэкап базы в `data/backups/`, хранятся 14 последних.

## Деплой на сервер одной командой

```bash
cd ~/Desktop/тима
./deploy.sh root@IP_СЕРВЕРА
```

Скрипт сам поставит Docker, если его нет, зальёт код (без `.venv`, `.git` и базы),
соберёт образ, поднимет контейнер и покажет логи. Пароль от сервера спросит один раз.
Повторный запуск — это обновление: база и настройки на сервере не трогаются.

## Запуск на сервере (вручную)

1. **Создай бота** у [@BotFather](https://t.me/BotFather) → `/newbot` → получи токен.
2. **Добавь бота администратором в канал**, на который проверяем подписку.
   Без прав администратора Telegram не даст проверить подписку — это его ограничение, не бага бота.
   Если используешь закрытый канал для выдачи доступа — там бот тоже должен быть админом
   с правом приглашать по ссылке.
3. **Узнай свой Telegram ID** — напиши [@userinfobot](https://t.me/userinfobot).
4. Положи проект на сервер и настрой окружение:

```bash
cp .env.example .env
nano .env          # BOT_TOKEN и ADMIN_IDS обязательны
mkdir -p data && chown -R 1000:1000 data   # иначе SQLite не сможет открыть базу
docker compose up -d --build
docker compose logs -f
```

⚠️ `chown -R 1000:1000 data` обязателен при бинд-маунте: процесс в контейнере работает под
непривилегированным пользователем, а папку docker создаёт от root. Симптом, если забыть —
`sqlite3.OperationalError: unable to open database file`.

5. (необязательно) Залей шаблон воронки — материал и три прогрева-заглушки:

```bash
docker compose exec bot python -m bot.seed
```

6. Открой бота в Telegram, отправь `/admin`.

### Первичная настройка в админке

| Шаг | Где | Что делать |
|---|---|---|
| 1 | 🎬 Медиатека | Залей кружок приветствия и все файлы материала |
| 2 | ⚙️ Настройки → 📢 Канал | Пришли `@username` канала или перешли пост из него |
| 3 | ⚙️ Настройки → ⭕️ Кружок | Выбери кружок из медиатеки |
| 4 | ⚙️ Настройки → ✏️ Тексты | Поправь текст меню и остальные тексты под себя |
| 5 | 🎁 Материал | Добавь блоки: файлы, видео, тексты со ссылками |
| 6 | 🔥 Прогрев | Добавь шаги: задержка → контент → кнопки → 🔒 если нужен гейт |
| 7 | 🔥 Прогрев → ▶️ Прогнать на себе | Проверь всю цепочку за пару минут |

## Тестовый контур → прод

Канал не зашит в код, он лежит в настройках. Порядок такой:

1. Создай тестовый канал, добавь туда бота админом.
2. В админке поставь этот канал и гоняй сценарий: `/start`, `/reset`, «Прогнать на себе».
3. Когда всё нравится — ⚙️ Настройки → 📢 Канал → пришли боевой канал. Бот проверит,
   что он там админ, и сохранит.
4. Почисти тестовые прохождения: `/reset` для себя; если нужно вычистить базу целиком —
   останови контейнер и удали `data/bot.db` (медиатека и настройки лежат там же,
   так что лучше сначала выгрузить цепочку через 🔥 Прогрев → ⬇️ Экспорт).

⚠️ **Важно про смену токена.** `file_id` в Telegram привязан к конкретному боту.
Если переезжаешь на другого бота — медиатеку надо залить заново. Структуру прогрева
при этом перенесёшь экспортом/импортом JSON (медиа подтянется по именам из медиатеки).

## Ручной чек-лист перед боем

- [ ] `/start` с чистого аккаунта: пришёл кружок, пришло меню с двумя кнопками
- [ ] Кнопка «Подписаться» открывает нужный канал
- [ ] «Я подписан» без подписки → всплывашка, материал не выдан
- [ ] Подписался → «Я подписан» → материал пришёл целиком, ссылка в закрытый канал работает
- [ ] Повторный `/start` не выдаёт материал второй раз
- [ ] «Прогнать на себе»: все шаги пришли по порядку, 🔒-шаг проверяет подписку
- [ ] Отписался от канала → 🔒-шаг не пришёл, пришло напоминание
- [ ] Рассылка: предпросмотр совпадает с тем, что уходит людям
- [ ] Рассылка на сегмент: число получателей совпадает со статистикой
- [ ] Запланированная рассылка ушла в назначенное время
- [ ] Выгрузка CSV открывается в Excel, кириллица не битая

## Разработка

```bash
make install    # venv + зависимости
make test       # 82 теста
make run        # запуск локально (нужен .env)
make seed       # шаблон воронки, если база пустая
```

⚠️ Если в папке лежит `.venv-agent` — это Linux-окружение из рабочей сессии, на macOS оно не запустится.
Свой venv создавай командой `make install`.

Структура:

```
bot/
  __main__.py        точка входа
  config.py          переменные окружения
  db.py / schema.sql база
  content.py         текст + медиа + кнопки → отправка
  sender.py          лимит скорости, 429, 403
  subscription.py    проверка подписки
  scheduler.py       тик прогрева раз в минуту
  broadcast.py       движок рассылок
  services.py        сценарии: старт, проверка, выдача материала
  repo/              users, media, funnel, material, broadcasts, settings
  handlers/          user.py + admin/ (media, funnel, material, settings, stats, broadcast)
tests/               pytest
```

## Если хостер блокирует Telegram

Признак — бот виснет после «База подключена», а `curl https://api.telegram.org` с сервера
отваливается по таймауту. Лечится одной строкой в `.env`: зеркало API на Cloudflare Worker
(`TELEGRAM_API_BASE`) или SOCKS5-прокси на чистый сервер (`TELEGRAM_PROXY`).
Подробности и готовые рецепты — в `docs/telegram-proxy.md`.

## Эксплуатация

```bash
docker compose logs -f --tail=100   # логи
docker compose restart              # перезапуск (очередь и рассылки продолжатся)
ls data/backups/                    # ежедневные бэкапы базы
```

Восстановление из бэкапа: останови контейнер, скопируй нужный файл в `data/bot.db`, запусти снова.
